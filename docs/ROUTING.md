# Carried-piece routing

The computer-side route planner represents the 8×8 board on an integer half-square grid. Square centers are odd/odd: `a1=(1,1)` and `h8=(15,15)`. The 32 parking slots are even/even intersections around the perimeter, using the mapping in `firmware/include/KnightRoute.h`. A route includes pickup and delivery points.

The planner connects a square center diagonally to a neighboring grid intersection, travels along horizontal or vertical grid lines, and enters the destination square diagonally. It may use a vacant edge-square center to reach a corner slot blocked by occupied adjacent parking slots. It avoids passing through occupied centers and occupied parking slots. Straight grid runs are compressed into turn points; every diagonal endpoint is retained so the Uno accepts the segment. If the shortest path exceeds a waypoint cap, the planner searches for another route with fewer turns before failing explicitly.

`plan_transfer_route()` works from the occupancy snapshot **before one transfer**. After a capture victim is parked, the caller must update square and slot occupancy before routing the attacking piece. `find_reachable_parking_slot()` tries vacant slots in order; `ReachableParkingSlotSelector` integrates that search with the logical move planner, including capture-promotion sequences.

Without measured `RouteGeometry`, a path is only a topological candidate. Checked routing requires the X/Y travel spans, end inset, pulses-per-mm scale, board pitch, moving and stationary piece diameters, and a clearance margin. Supply the current board origins too, especially after referencing saved geometry. Read these machine values from the framed `GEOM` command after `HOME` or `REF`. The planner maps every waypoint through the same perimeter clamp and pulse rounding used by the firmware, then applies a circular center-distance check in millimeters. This matters because a clamped perimeter run can be closer to first-rank pieces than its ideal grid line. `GEOM` rounds values to four decimals, so the margin must also account for that and for path tracking and physical centering error. The model still does not account for magnet coupling, piece wobble, board misalignment, or neighboring pieces being displaced. Physical route tests are required before loaded game operation.

The host tests cover all 4,032 distinct square pairs and all 64×32 square/parking pairs in both directions with empty perimeter storage. Every nominal route in this matrix fits the Uno's 12-point `CARRY` command and passes its segment-shape rules. A more obstructed route can exceed 12 points; the host then searches for a lower-turn route and rejects it if none fits. This test evidence proves the software topology and encoding, not that the board can physically carry each piece.
