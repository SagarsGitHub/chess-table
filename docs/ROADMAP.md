# Roadmap

The target is a chess table that can complete a full game, park captured pieces around the perimeter, and recover predictably from interrupted motion. A stage is complete only when its acceptance evidence is recorded in this repository.

**Current sequence:** Stage 1 electrical diagnosis is deferred at the user's request. Stage 2 and the software/simulator portion of stage 3 are implemented. The user reports that the empty-board physical test passed and supplied `GEOM X=249.7350 Y=251.9850 OX=-0.1325 OY=0.9925 P=31.2500 I=2.0000 PPM=133.3333`. Stage 4 has a checkpointed game runner, Stockfish integration, and a local browser GUI. An earlier physical Stockfish self-play reached 155 committed plies and 24 occupied parking slots, then stopped during the next carry. A later physical GUI game reached a 126-ply draw with 20 occupied parking slots. The user reports its physical reset worked after a parked-piece routing fix; the saved state records all 32 pieces home and parking empty. The reset did encounter an `ERR MOTION`, controller reboot, and reconciliation, so fault-free loaded reliability remains open. The host has tight-route fallback, direct diagonal routing, automatic advancement after `DONE CARRY`, a checkpointed reset, and a perimeter parking display. The user reports that the slower loaded-motion refinements work on the board; repeatability and firmware revision evidence still need recording. During actual board movement, a limit closure must persist for 3 ms to stop motion. Switch activity at idle and between movement segments is ignored. Homing uses the first raw edge and confirms it after stopping. The table uses explicit human move entry and checkpointed expected occupancy; physical piece sensing is out of scope. Faults and uncertain outcomes require physical reconciliation.

The pieces currently balance on a ferrite rod that protrudes slightly below each base. Treat contact drag as a separate hardware variable while tuning motion. On one piece, compare a thin low-friction skid over the contact point with a stable three-pad base that keeps the rod clear of the board. Measure sliding force with the magnet off and on, and observe coupling, rocking, neighboring displacement, and board marks over repeated carries before modifying the full set. Any added pad thickness can reduce magnetic coupling by increasing the gap.

At the measured 31.25 mm pitch, two 18 mm standing pieces leave a 13.25 mm gap for an 18 mm moving piece. Slowing a crowded horizontal carry reduces impact but cannot create geometric clearance. Moving neighbors aside would require additional tracked transfers and recovery steps, so test the slower segment profile and PTFE treatment first.

## Full-game GUI

The GUI is a local front end to the checkpointed host runner. It must use the same legal-move, parking, routing, Stockfish, and serial code as the CLI; one session owns the Uno and the game-state file. It accepts explicit human moves because the table has no physical sensing. In normal play, a matched `DONE CARRY` advances the expected physical state without routine move-by-move confirmation. Simulation proves host and interface behavior only; it does not establish loaded physical acceptance.

## Fixed promotion rule

There are no spare queens, rooks, bishops, or knights for promotion. The pawn remains the physical piece on the board while the rules engine and Stockfish use the selected promoted type. Later moves carry that same pawn; capture parks it as a pawn. The game runner does not swap in a parked piece or request a manual replacement. Record both the legal and physical identities in game checkpoints and operator-facing state.
