# Roadmap

The target is a chess table that can complete a full game, park captured pieces around the perimeter, and recover predictably from interrupted motion. A stage is complete only when its acceptance evidence is recorded in this repository.

**Current sequence:** Stage 1 electrical diagnosis is deferred at the user's request. Stage 2 and the software/simulator portion of stage 3 are implemented. The user reports that the empty-board physical test passed and supplied `GEOM X=249.7350 Y=251.9850 OX=-0.1325 OY=0.9925 P=31.2500 I=2.0000 PPM=133.3333`. Stage 4 has a checkpointed game runner, Stockfish integration, and a local browser GUI. Physical Stockfish self-play reached 155 committed plies and 24 occupied parking slots on 2026-10-05, then stopped during the next carry; full-game acceptance remains open. A later physical GUI game reached a 126-ply draw with 20 occupied parking slots; its reset was blocked in preflight by a parked-piece exit cycle, with no reset `CARRY` sent. A tight-route fallback and automatic advancement after `DONE CARRY` are implemented in host software. Direct diagonal routing, a gentler loaded profile, and a checkpointed reset-board command are implemented. The user reports that the short physical refinement tests worked; the later reset-order and parked-piece staging changes still need a loaded physical check. The GUI has completed simulated games and reset runs; detailed loaded acceptance and a complete physical reset remain open. During actual board movement, a limit closure must persist for 3 ms to stop motion. Switch activity at idle and between movement segments is ignored. Homing uses the first raw edge and confirms it after stopping. This table will use explicit human move entry and checkpointed expected occupancy throughout its life; physical piece sensing is out of scope. Faults and uncertain outcomes require physical reconciliation.

## Full-game GUI

The GUI is a local front end to the checkpointed host runner. It must use the same legal-move, parking, routing, Stockfish, and serial code as the CLI; one session owns the Uno and the game-state file. It accepts explicit human moves because the table has no physical sensing. In normal play, a matched `DONE CARRY` advances the expected physical state without routine move-by-move confirmation. Simulation proves host and interface behavior only; it does not establish loaded physical acceptance.

## Fixed promotion rule

There are no spare queens, rooks, bishops, or knights for promotion. The pawn remains the physical piece on the board while the rules engine and Stockfish use the selected promoted type. Later moves carry that same pawn; capture parks it as a pawn. The game runner does not swap in a parked piece or request a manual replacement. Record both the legal and physical identities in game checkpoints and operator-facing state.
